# V0.15 店铺官方接入与上下架

本版把「店铺登记」扩展成前后端可执行的已有商品上下架流程。淘宝 / 天猫和抖店使用官方签名接口；页面不保存凭证值。平台选择改成可用键盘操作的卡片单选。

## 当前范围

| 能力 | 实现与限制 |
| --- | --- |
| 店铺身份核验 | 使用授权凭证读取身份，并核对配置的店铺 ID |
| 商品读取 | 在售 / 仓库分页列表，20 件一页；操作前单独读取商品详情 |
| 上架 / 下架 | 逐件确认后调用平台接口，提交后回查状态，保存操作记录 |
| 防重复 | 操作 ID 去重，同商品待核验时阻止新操作，重启不重发 |
| 原生 OAuth 授权页 / 自动续期 | 尚未实现；本版适用于已有应用和店铺授权的用户，绑定现有 access token |
| 新建商品 | 未实现。需要另外处理类目、属性、资质、图片、SKU 和运费模板 |
| 其他平台 / 服务商网关 | 保留店铺登记、只读网关身份检查，不支持写商品 |
| 协作目标 | 继续准备草案；本版实际上下架从「AI基础能力配置 → 店铺连接 → 管理商品」发起，未开放给 Agent 自主写店铺 |

## 已有授权时如何接入

1. 部署完整 Node.js 后端。GitHub Pages 和下载的免安装 HTML 只能看交互，不能保管密钥或执行店铺操作。
2. 在服务器创建 `.env`（不要提交 Git）。参考项目 `.env.example`：

```dotenv
PLATFORM_TOKEN=自行生成的管理员访问令牌
AGENT_ALLOWED_HOSTS=eco.taobao.com,openapi-fxg.jinritemai.com
STORE_APP_KEY_PRIMARY=开放平台应用AppKey或AppID
STORE_APP_SECRET_PRIMARY=开放平台应用AppSecret
STORE_ACCESS_TOKEN_PRIMARY=该店铺已授权的access_token
```

已有模型、供应商等域名需合并保留。环境自身的出站网络策略也需要允许对应官方域名。淘宝 / 天猫使用 `eco.taobao.com`，抖店使用 `openapi-fxg.jinritemai.com`。

3. 用 `node --env-file=.env src/server.js` 启动，在网页输入 `PLATFORM_TOKEN` 登录。真实写操作必须配置该访问令牌。系统按单管理员信任模型运行，多工作空间不等于多租户权限隔离；同一个数据目录只运行一个后端进程，并使用持久化磁盘。
4. 添加店铺，选择平台和「官方接口直连」，填写名称、公开网址和官方店铺 ID。三个凭证字段分别填变量名称 `STORE_APP_KEY_PRIMARY`、`STORE_APP_SECRET_PRIMARY`、`STORE_ACCESS_TOKEN_PRIMARY`，不要填值。
5. 勾选「允许人工确认后提交商品上下架」，保存，再点「检查授权」。通过只说明店铺身份可读取，不代表已获得写权限；缺少商品接口权限时平台会拒绝相应动作。
6. 点「管理商品」，选择在售 / 仓库，核对真实商品。上架 / 下架按钮会先准备确认单。确认窗口展示店铺、商品 ID、名称、当前和目标状态；淘宝上架还展示刚读取的库存数量。
7. 勾选明确确认，才提交真实操作。每次只处理一件商品，确认单 5 分钟有效；提交前重新检查店铺配置版本、商品状态、库存和更新时间。
8. 令牌失效时在服务器更新授权令牌并重启，再检查授权。本版不自动续期。不要把密钥、Cookie 或密码发到聊天或粘贴到店铺网址。

多个店铺使用不同变量后缀，如 `_TAOBAO_A`、`_DOUYIN_B`，分别绑定到对应连接。应用和授权必须属于配置的店铺。生产首轮联调请选定一件允许操作的商品，先读身份与列表，再明确确认写操作。

## 页面点击与异常分支

| 触发 | 接下来发生什么 | 异常与恢复 |
| --- | --- | --- |
| 保存连接 | 保存非敏感配置，版本加一，旧授权检查失效 | 正整数店铺 ID、HTTPS 地址、凭证变量前缀不合规则留在表单显示原因 |
| 检查授权 | 官方接口回查店铺 ID | 错店、缺变量、网络未放行、过期 / 缺权限显示失败，不假装已连接 |
| 管理商品 / 切页 | 身份核对后读取商品 | 错误展示在商品列表上方，可刷新；不填充演示商品 |
| 点商品上架 / 下架 | 获取当前详情，创建待确认记录 | 已为目标状态、未知 / 删除状态、淘宝库存不足、抖店审核未通过则停止 |
| 取消确认 | 不调用任何写接口，待确认记录保留 | 5 分钟过期后重新选择商品 |
| 确认提交 | 先持久化提交标记，再调用平台；同一记录只提交一次 | 版本或商品变更为「未提交」，请刷新重建确认单 |
| 平台明确拒绝 | 保留「平台拒绝」及安全错误码 | 到开放平台排查权限、授权与审核状态，然后重新准备操作 |
| 平台受理 | 自动回读商品详情 | 仍是原状态显示「等待平台更新」，点击回查只读不重发 |
| 超时 / 断网 / 无法解析响应 | 标记「结果待核验」 | 点击回查；同商品不能继续写。重启也不自动重发 |
| 回查为目标状态 | 标记「平台状态已确认」，保存观察结果和核验时间 | 表示目前商品确处于目标状态，不推断是哪次操作导致，不代表销售或经营收益 |
| 在商家后台完成核对 | 填写至少 10 字核对记录后人工结束 | 记录为「已人工结束」，不伪装成功；管理员确认无待执行请求后才重新发起 |

## 技术接口与实现

- `src/store-native.js`：固定官方域名、TOP MD5 / 抖店 HMAC-SHA256 签名、20 秒超时、禁止重定向、2MB 响应限制、凭证回显拒绝、安全错误消息。
- `src/store-operations.js`：持久化确认、版本与商品快照核对、提交前落盘、同商品互斥、重复确认去重、回查及人工结束。
- `public/store-operations.js`：商品列表、操作确认、操作记录、核验与恢复。
- 平台 ID 全程保留字符串。抖店写接口要求数字 JSON 的商品 ID，由严格校验后的十进制字符串原样序列化，避免 19 位整数被 JavaScript 浮点数舍入。
- 不把凭证、签名 URL、平台完整错误正文写入操作记录。令牌及密钥只由服务器环境变量注入。

| 平台 | 读取 | 写入 |
| --- | --- | --- |
| 淘宝 / 天猫 | `taobao.shop.seller.get`、`taobao.items.onsale.get`、`taobao.items.inventory.get`、`taobao.item.seller.get` | `taobao.item.update.listing`、`taobao.item.update.delisting` |
| 抖店 | `shop.reputation`、`product.listV2`、`product.detail` | `product.setOnline`、`product.setOffline` |

淘宝上架接口要求 `num`：本版仅采用刚读取且再次核对的有效库存，页面明确展示，不猜测库存。平台在检查与写入之间仍可能发生外部变更，官方接口不提供本应用的原子比较与交换，故不能保证跨商家后台、跨应用的并发修改隔离。

HTTP 路径均属于当前 `X-Workspace-ID`，并受 `PLATFORM_TOKEN` 和跨站写入检查保护：

- `POST /api/integrations/stores/:store/products`：`{state:"online"|"offline",page:1}`。
- `GET /api/integrations/stores/:store/operations`：最近 100 条记录。
- `POST /api/integrations/stores/:store/operations`：`{productId:"…",action:"online"|"offline"}` 创建确认单。
- `POST /api/integrations/stores/:store/operations/:operation/confirm`：`{confirmed:true}`。
- 同路径 `/verify`：`{}`，只回查。
- 同路径 `/resolve`：`{confirmed:true,note:"商家后台核对记录…"}`。

## 验证证据与尚待验证

已增加状态机、协议、长 ID、重复提交、重启恢复等测试；浏览器通过本地模拟官方 API 验证页面到后端签名适配器的上下架流程。测试假平台仅在显式加载 `scripts/fixtures/store-platform.mjs` 时启用，`npm start` 不会加载它。

当前环境没有真实应用凭证，未对用户真实店铺执行上下架。平台接口是否对该应用开放、当前版本字段及特定类目规则需用用户授权完成联调。官方文档站被本环境网络策略阻止，本次协议参考公开 SDK 源码并完成模拟响应契约验证：抖店 `zsmhub/doudian-sdk`（26f48a9）、`whalesky-labs/doudian-sdk`（c223847）；TOP 签名及上下架参数交叉参考 `wangyu0248/TaobaoOpenPythonSDK` 与 `fengjinqi/taobao-sdk-python`。SDK 镜像有版本时效限制，模拟通过不能替代官方账号验收。

验收结果：128 项自动测试通过；完整后端与离线预览的店铺浏览器检查通过，包括卡片选择、确认取消、上下架回查、记录刷新保留及 390px 手机布局。工作空间、知识库、搜索配置和店铺目标关联另行回归。浏览器截图中的店铺及商品明确标注为模拟平台 / 测试商品。
