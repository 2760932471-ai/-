# 自动内容制作与图片交付 · V0.18

## 修复的问题

原来的总控把图片目标匹配到 `copy.image_brief`，该能力只生成文字简报。主图员工和协调员工输出文字后，目标就进入验收；内容表单还要求用户逐项填写卖点、人群和来源。这不能满足“找商品并生成图片”的目标。

现在图片目标走独立制作调度：自动查找已有来源 → 整理特点与建议人群 → 调用图片服务 → 保存 PNG → 验收图片。只输出简报时不能进入图片验收。

## 用户怎样操作

新建目标，例如“在1688搜寻合适的水龙头产品，并生成商品主图和商品详情页图片”。默认总控自动匹配，系统保存目标后会自动推进，无需再次确认分工或逐项填写制作资料。

- 已连接搜索或供应商来源时，先运行已有检索与同步；知识库中的可追溯报价也可用。指定 1688 时，只接受来源注明 1688 的候选，不把其他渠道报价称为 1688 结果。来源文字由资料提供方登记，不等于已经独立核实供应商身份。
- 在有记录的候选中按报价初筛一个商品，并说明未核实质量、库存和运费，不宣称“综合最优”。这仍是基础选品规则，并非完整自主采购。
- 从知识库和已审核可用的来源文档提取参数型特点，保留出处、文档 ID 和版本。不会把“嗯嗯”等占位文字当作卖点或证据。
- 自动根据商品给出目标人群建议，明确标注“系统建议，可调整”。当前这部分是检索与规则提取，不是大模型进行用户研究，也不能视作已验证的客户画像。
- 有同 SKU、已审核授权的商品图时优先作为参考图；否则按概念稿生成并标注。找不到实际候选记录的选品目标会说明来源连接缺口，不偷偷编造产品。只有商品品类的纯生图目标可生成概念画面。
- 未指定渠道时默认“全渠道”。全渠道表示通用内容方向，不代表已上传所有店铺、已核验每个平台规范或已生成全部平台尺寸。
- 要求主图和详情页图片时，分别生成一张 1:1 主图和一张 2:3 详情模块。目前不是完整多屏详情长图。每个版本默认最多两张，使用已配置图片 API 额度。
- 图片直接显示在群聊和交付物中，点击可看大图或下载。文字设计简报仅作为历史或过程资料，不能替代图片完成标准。

“资料”页默认展示自动整理结果、建议人群和证据。人工表单折叠到“调整制作资料（可选）”；只有确实要修改时才打开。文字工作应用只需输入商品名，其他字段可以留空；总控识别到纯文字制作任务且商品明确时也可自动启动。

## 渠道和交付类型

发布渠道选项为全渠道、淘宝 / 天猫、抖音、小红书、京东、拼多多、1688、自有商城。商品主图、详情页图片、标题、视频属于交付类型，不再混入渠道选项。旧数据中的“商品详情页”渠道按全渠道兼容，原记录保留。

## 阻塞、变更与恢复

- **没有商品名称**：只询问需要制作哪种商品，不要求用户补齐整套营销资料。
- **没有商品来源**：选品目标停在来源连接环节。搜索结果摘要不等于商品参数，当前没有实现任意网页正文的通用抓取解析；仅有网页线索时，需要可读取商品记录的供应商接口或知识库资料。
- **没有生图连接**：显示连接问题，不生成替代文字冒充结果。配置好后，未提交的任务会随下一次调度继续。
- **失败或结果未知**：保留错误，阻止验收，不自动重复请求。核对服务费用后，可修改制作偏好建立新版本，再生成；旧失败版本不自动重试。
- **来源失效**：引用的知识被删除、停用或换版，素材授权发生变化时，旧任务不再继续调用或提供失效结果下载。调度前后校验资料快照，避免改版期间把旧信息用于新图片。
- **暂停与版本修改**：暂停不再派发新任务；新版本不会套用旧图片。已发出的服务请求可能已经产生费用，不能靠暂停撤回。
- **重启**：已完成图片不会重复提交；中断任务仍沿用“结果未确认”规则。
- **旧目标**：未结束的图片目标会转到新图片流程；已经验收结束的目标不会自动重跑。历史文字简报继续保留。

上线、上下架、调价等真实店铺操作继续走原有业务授权流程。本次自动化的是资料整理与内容制作，没有扩大店铺写权限。

## 验证与运行边界

155 项自动化测试通过。浏览器验证了：来源报价 → 自动整理 → 双图片任务 → PNG 缩略图与交付 → 验收；并验证静态预览的连接阻塞、渠道默认和免填卖点入口。图片接口使用模拟 PNG，未完成真实 Gemini 或真实 1688 的线上联调。

当前开发环境的 Google 域名和密钥尚未生效；这不代表用户自己部署的服务器配置状态。真实运行应在完整后端核对 Gemini、搜索和供应商接入。GitHub Pages 始终只作交互预览。

Codespaces / 自建服务器更新：在仓库目录停止旧服务，运行 `git pull --ff-only origin main` 后用原环境变量重新 `npm start`。保留 `.data`、`.env` 和已有密钥配置，不删除历史数据。若本地有未提交修改，先保留并处理，勿强制覆盖。
