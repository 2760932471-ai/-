# V0.9 内容制作与聊天 @ 修复

## 使用路径

保留“新建目标”作为通用入口，支持选择员工并确认计划。增加 **能力中心 → 内容制作** 作为明确、只读内容工作的快捷入口。默认有 17 位员工（12 类基础员工 + 5 位内容专员）、21 个代码 Skill。升级补充新专员，保留原有员工名称、停用状态、模型与 Skill 配置。

| 内容专员 | 能力 | 当前交付 |
| --- | --- | --- |
| 商品标题 | `copy.titles` | 3 个信息顺序不同的标题候选、字符数、取舍说明 |
| 卖点文案 | `copy.selling_points` | 基于确认特点的短卖点、参数说明、来源对应 |
| 详情页文案 | `copy.detail` | 首屏、参数、细节、选购、售后五个文字模块及缺失素材 |
| 短视频脚本 | `copy.video` | 30 / 60 秒分镜、画面、口播与字幕 |
| 主图策划 | `copy.image_brief` | 3 个构图方向、画面文字、素材清单；不生成图片 |

这是可直接运行的代码编排，不是已接通的通用模型创作。渠道和受众写入简报作为审稿背景；尚未接入各渠道规则、词库、搜索量或语义创作。商品特点须人工确认，来源随成果保存；目前不从知识召回中自动提取并确认新事实。

## 内容制作交互与状态

1. 点击卡片“开始制作”，或在对应内容专员卡片点击“交给他一个目标”，打开内容资料表。通用“新建目标”仍可自行装配多个员工。
2. 填商品名称、渠道、受众、1–8 条已核验特点、资料来源。每条特点最多 120 字；视频时长可选 30 / 60 秒。“填入虚构样例”明确标注测试数据，并取消确认勾选。
3. 点击“生成内容草稿”前必须勾选核验。提交时禁用按钮并显示保存状态。服务端在同一事务中保存目标、确认资料、创建计划并入队；这个按钮本身就是本次只读制作的执行指令，无需再走一次通用计划确认。
4. 成功后关闭表单，打开目标“交付物”，等待执行并自动刷新。点击“预览完整内容”查看文字，或下载 Markdown。运行记录保留输入快照、Skill 执行和结果。
5. 员工交付后进入待验收阶段。人工可查看来源和完整草稿，再验收；没有真实发布动作。
6. “资料”页可查看内容简报；准备或执行阶段修改并保存，将增加版本、使旧排队结果失效、回到计划确认。已经交付后，使用“沿用资料，再做一版”创建新的独立目标，保留旧成果。
7. 可以切到“讨论”并 @ 内容专员。基础代码员工使用保存的资料重跑其已装配能力；聊天中的修改意见不会自行覆盖确认事实。若需要开放式改写，后续配置并验证模型连接。

### 异常处理

| 条件 | 系统行为 | 用户下一步 |
| --- | --- | --- |
| 缺资料、未确认、特点过长或过多 | 表单保留，显示原因；不创建目标、不排队 | 补齐后重新提交 |
| 命中有限的待核验宣传词 | 停止草稿生成并列出表述 | 核验并改写；有限词表不代表完整合规检查 |
| 同一次提交重复发送 | 同一请求编号、同一内容只返回原目标 | 可安全重试相同请求 |
| 已创建请求的内容发生变化 | 拒绝覆盖原目标 | 回到已创建目标查看，或关闭表单后新建一版 |
| 快捷入口员工被停用、改成模型模式或换了能力 | 禁用快捷按钮；后端也校验并拒绝 | 检查员工配置；自定义编排使用“新建目标” |
| 执行中保存新资料 | 旧版本运行丢弃或不应用，保留记录 | 确认新版本计划后执行 |
| 队列满、服务错误或浏览器存储满 | 原子提交失败；显示错误，不假称成功 | 保留输入，解决问题后重试 |
| 执行失败 / 待补资料 | 任务页显示阻塞，交付物不显示虚假成功 | 查看运行记录、补资料并重试 |

## 协作聊天 @

原来的候选触发要求 @ 前有空格；“请@内容员工”不弹列表。同时旧版目标不挂载新的选人组件。本版统一聊天入口并补充以下交互：

- 输入 `@` 或 `＠` 可匹配员工；中文、标点紧贴 @ 也支持。邮箱地址中的 @ 不作为提及处理。
- 明确的 **“@ 选择员工”** 按钮打开可搜索的员工列表，鼠标和手机可直接点击选择。候选插入实际姓名并记录员工 ID，同名时按选中 ID 区分。
- 可选择本群外的就绪员工。发送时原子加入讨论并为其排队回复；不增加执行计划成员、不更改任务授权或目标版本。
- 每条消息最多 @ 4 人，讨论成员最多 24 人、队列最多 24 条。超过限制、员工未就绪、未知姓名或正文与选择不一致时显示错误并保留草稿。
- 中文输入法确认键不发送消息；候选列表内方向键选择、Enter 插入、Escape 收起。普通消息 Enter 发送，Shift + Enter 换行。
- 旧版目标保留原来的执行模式、任务、交付物与成员。首次使用新聊天操作时启用员工讨论；旧队列尚有待回复项时提示等回复完成后再试。
- 消息、引用、上下文设置与讨论成员持久化。服务器版使用 `.data/platform.json`，静态预览使用当前浏览器原有 localStorage key。无需清空旧数据。

## 接口与执行边界

`POST /api/goals` 扩展可选 `contentDraft`（工作包 ID）与 `copyBrief`；快捷入口必须且只能选择对应专员，并检查其为仅挂载对应能力的代码模式。现有请求编号保证创建幂等。`POST /api/goals/:id/actions` 的 `inputs` 支持 `copyBrief`。

消息动作增加 `inviteIds`、`workforceChat`；邀请名单必须与本条实际提及对应。`mentionIds` 继续用于选人和同名消歧。自动加入只是加入当前讨论，不触发目标分工或发布。

## 验证与复现

- `npm run check`、`npm test`：89 项自动化测试通过，包括 5 个内容能力、输入阻断、重复请求、旧版本结果、中文 / 全角 @、自动邀请与旧目标兼容。
- 浏览器：服务器 HTTP 版和断网静态预览都走通标题、视频、交付查看、再做一版、手机选人、输入法 Enter、刷新恢复、旧会话回复，检查 375 / 768 / 1440 px 无横向溢出。
- 可复用测试：`scripts/check-ui.mjs`。先启动测试用后端，设置 `UI_TEST_URL`，安装 Playwright 后运行 `node scripts/check-ui.mjs`；静态版加 `--offline`。可用 `PLAYWRIGHT_MODULE` 指定模块 URL，`CHROMIUM_PATH` 指定浏览器路径。请使用专门的测试工作空间，脚本会创建样例目标；断网模式只验证静态 HTML 与浏览器存储，未验证直接 file:// 打开。
- 尚未使用用户真实模型、外部 Agent 或店铺账号联调。图片 / 视频生成、自动排版和真实发布仍未实现。
