# 在本地获取项目、打开界面并继续工作

## 先确认三个问题

- ZIP 是压缩包，文件预览器不支持它并不代表里面的项目损坏。必须先下载并解压才能使用；如果附件链路不可用，直接从 GitHub 克隆，无需 ZIP。
- 云环境的 `/workspace` 不是你的电脑目录。只有克隆、拉取或手动复制后，本地才有这些文件。
- 项目文件、平台群聊和本次 Codex 对话是三类不同内容，不会自动互相同步。

## 不使用聊天附件获取项目

仓库地址：<https://github.com/2760932471-ai/->。

方式一：在 GitHub Desktop 中选择 **File → Clone repository → URL**，填写上面的仓库地址，选择本地目录。仓库私有时使用具有权限的 GitHub 账户登录。

方式二：电脑已安装 Git 时，在终端执行：

```sh
git clone --branch main https://github.com/2760932471-ai/-.git ai-workbench
cd ai-workbench
```

如果已经克隆过，先在该目录执行 `git status` 查看自己的改动，再用 `git pull --ff-only` 获取更新；不要用覆盖或强制重置来处理本地改动。

## 只想看界面

在本地文件管理器找到 `deliverables/ai-platform-preview.html`，右键选择 Chrome、Edge 或 Safari 打开。没有网络、Node.js 或后端时也能用。

如果看到 HTML 源码，说明文件被文本编辑器、GitHub 文件页面或附件查看器打开了。请将本地 HTML 文件交给浏览器，不要把 ZIP 拖入文件预览器。

预览包含新建目标、群聊、Agent 配置与计算测试、资料录入、交付物、运行记录及模拟审批。页面顶部明确显示“免安装预览”。数据只保存在当前浏览器，外部 Agent 不能从预览调用。

如果浏览器受单位策略限制不允许本地文件运行，可以使用下面的本地后端方式。项目当前没有已核验的公网部署地址，GitHub 的 HTML 文件页面也不是运行中的网页。

## 运行完整前后端

安装 Node.js 22 或更高版本后，在项目根目录：

- Windows：双击 `start-platform.cmd`，保留终端窗口运行。
- macOS / Linux：终端执行 `bash start-platform.sh`。
- 或者直接执行 `npm start`。

服务默认端口 3000。在**启动服务的同一台电脑**，浏览器地址栏输入 `http://127.0.0.1:3000`。它不是远程分享链接，也不是手机或另一台电脑都能直接使用的地址。

无需 `npm install`，当前没有第三方运行依赖。`.env.example` 说明可选配置；启动脚本读取 `.env`，`npm start` 使用进程环境。

如果提示端口已占用，先检查是否已有该项目在运行，不要随意停止其他程序；可在 `.env` 中设置其他 `PORT` 后用启动脚本运行。

## 聊天记录为什么没跟过来

| 内容 | 实际保存位置 | 克隆仓库后是否存在 |
| --- | --- | --- |
| 本次与你协作的 Codex 对话 | 当前会话所在产品 | 不会自动出现在本地客户端聊天列表 |
| 需求、决定、当前进度 | 根目录 `PROJECT_CONTEXT.md` | 会随 Git 文件同步 |
| 平台内的目标、群聊、运行记录 | 完整后端的 `.data/platform.json` | 不会；运行数据不提交到仓库 |
| 免安装演示中输入的数据 | 当前浏览器存储或页面内存 | 不会；更换浏览器/电脑不会自动迁移 |
