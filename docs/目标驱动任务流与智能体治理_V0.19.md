# 目标驱动任务流与智能体治理 V0.19

## 产品定位与本次调整

平台以“目标 / 委托、任务流、执行实例、共享能力、治理规则”为核心。数字员工是可选的长期委托入口，不是执行目标的前置条件，也不再默认按人类岗位分工。长期委托的定时触发、独立记忆与主动跟进尚未在本版实现。

总控可以选择既有方法、组合任务、设计新方法与新能力。能力目录说明当前工具条件，不作为创造力白名单。新能力可以进入流程设计；“设计成立”“实现可用”“获准实际执行”“已交付”是不同状态。

本版实际实现：目标直接创建任务流；配置 API 模型后进行语义规划；无模型时使用明确标识的基础组合；模型可产生新能力提案；DAG 依赖调度和并行执行；真实代码 Skill、知识召回、搜索、模型分析及图片服务接入；未知能力保留设计；受阻时有限自动换路；验收后沉淀模板。

**尚未实现：任意新代码的自动隔离构建与测试、自动安装未知 MCP / 外部服务、跨用户企业权限体系、定期长期委托、多轮自动修复所有失败、任务流内直接写入店铺。** 不用“自主创造”掩盖执行器缺失；生成的新能力会显示待验证，不显示完成。

## 用户入口及交互

### 1. 新建目标

1. 点击“新建目标”，默认选择“目标总控 · 自动选择或创建任务流”。
2. 输入目标，点击“交给总控并开始”，无需先挑选员工，也无需填写岗位分工。
3. 服务端保存目标、讨论记录、知识范围及规划状态，前端立即进入协同工作台。
4. 后台选择模板或生成流程，展示方法、选择理由、每步验收标准和依赖关系。
5. 已知可执行步骤自动开始。独立分支并行，存在依赖的步骤等待所有必要前序完成。
6. 旧团队 / 旧规则模式仍可选择；历史目标不自动迁移或重新执行。

重复提交使用同一 requestId，返回已有目标；同一 ID 改内容会拒绝。无效目标不创建空记录。

### 2. 总控设置

“任务流 → 总控执行设置”选择规划模型，设置并行任务数、步骤数和每轮执行调用上限。模型复用“AI基础能力配置”已有 API 连接，需有效凭证及当前版本测试通过。

- 未选模型：基础规则组合，不宣称自主模型判断；通用分析任务会显示缺少模型。
- 已选但不可用：规划失败并说明原因，不偷偷降级伪造模型规划。
- 修改设置：后续规划使用新设置；已有流程保存设置快照。
- 修改了模型连接：旧版本执行需重新规划，避免默默改用另一模型。
- 并行上限 1–4，步骤数 2–16，执行调用上限 4–40；它们是资源控制，不是对方法的业务限制，也不是精确金额预算。
- 规划和分析目前使用 Chat Completions API 模型；本机 Codex 桥接的固定协议暂不用于此规划器。

### 3. 自主生成与新能力

模型收到目标、最近人类上下文、模板和当前工具条件，可以直接生成新任务图。每步包含目标、拟用方法、依赖与验收标准。未知能力允许附带描述、实现构想和测试要求，不因为“不在现有目录”而拒绝整份计划。

平台检查结构有效性：编号唯一、依赖存在、无环、最终核验覆盖全部必要分支。检查保证流程可追踪，不替代业务质量验证。

实际执行时，已连接能力正常调用；未知能力生成设计交付物并进入“新能力待验证”，绝不执行任意代码文本。接通隔离执行器之后，才能增加“构建 → 隔离测试 → 验证 → 晋升可调用能力”环节。真实账号、付款、外部发送、删除等影响仍需单独授权，模型不能自行扩大权限。

若遇到新能力未验证，配置了模型且尚未提交图片请求，本轮最多自动修订一次：把阻塞原因传给总控，请其考虑其他路径；历史构想保留、已用调用数累计。第二次仍不可执行就明确停下。普通接口失败、图片失败或未知扣费状态不自动反复重试。

### 4. 讨论与变更

- “补充上下文”：保存消息与引用；当前正在执行的任务继续使用原计划快照，避免进行中的任务无提示变化。本版该入口主要用于记录上下文，不承诺每条消息都触发模型对话。
- “请求变更并重新规划”：填写更新后的目标描述，生成新目标版本；总控结合最新描述和历史人类上下文规划。旧结果保留为历史。
- 运行中的旧版本结果返回时，标记 discarded，不写入新版本交付。
- 未发送的输入在轮询刷新中保留。
- 旧团队目标继续支持员工群聊与 @；新任务流不要求创建群成员。

### 5. 任务、结果与验收

任务卡展示方法、前置任务、验收标准、状态、执行次数和阻塞原因。后台把前序实际成果传入依赖节点；不要求人手工搬运成果。

知识与搜索提供证据，分析调用配置模型；网页摘要标为未核验线索。模型结论本身仍需业务审核。图片步骤等待真实服务返回 PNG 后才完成，不允许文字简报替代图片。

最终汇总节点在全部必要分支完成后执行，整理成果与来源。完成状态代表执行完成，不保证经营收益。用户在“复盘”验收后结束目标；可以在任务页“保存为可复用任务流”。相同目标版本重复保存只得到同一模板。

删除或停用知识、变更引用版本会使旧证据失效，最终验收拒绝采用失效引用。新能力草案尚未验证、步骤失败、图片未知结果时，均不能验收整个目标。

## 状态与异常

| 状态 / 事件 | 用户看到什么 | 系统处理 |
|---|---|---|
| planning / planning_running | 正在选择或创建任务流 | 保存规划快照，后台运行 |
| planning_failed | 原因与重新规划按钮 | 不凭空生成完成结果 |
| pending | 等待前置任务 | 前序全部成功才进入执行 |
| running | 运行中与调用记录 | 调用真实能力，保存结果 |
| needs_input | 明确缺少模型、资料或连接 | 连接 / 补充后重试，资料更新产生新版本 |
| needs_capability | 新能力构想、实现建议、验证要求 | 保留设计；有限自动换路或停止等待实现 |
| waiting_external | 等待真实图片 | 不重复提交；后台检查实际任务 |
| failed | 执行失败与原因 | 可重试普通只读任务；图片有提交记录时不自动重发 |
| 暂停 | 已暂停后续调度 | 不撤回已发出请求，保存返回结果，不开始后续任务 |
| 服务重启 | 运行中任务中断提示 | 不重复调用潜在付费请求；规划可重试 |
| 目标变更 | 新版本与保留的历史 | 丢弃旧版本迟到结果 |
| 调用上限到达 | 预算限制提示 | 停止新增执行，不无限循环 |
| review / completed | 待验收 / 已验收 | 只有必需任务真实完成才可结束 |

## 技术实现

- `src/taskflows/catalog.js`：跨岗位共享能力与基础任务流模板。
- `src/taskflows/planner.js`：基础组合、模型自主规划、结构验证，允许未知能力提案。
- `src/taskflows/manager.js`：实例状态、依赖调度、并行、调用记录、版本隔离、有限自动改路及模板沉淀。
- `public/flows.js`：任务流中心、总控设置、任务卡和目标资料。
- API：`GET /api/flows`、`PUT /api/flows/settings`、`POST /api/flows/goals/:id/template`；目标创建传 `executionMode: flow`，仍使用原有目标动作 API。
- 持久化：各工作空间自己的 platform.json，保留流程版本、实例状态、调用轨迹和模板；仍为单实例架构。
- 静态预览复用规则与状态代码；没有模型 / 搜索 / 生图后端，不把模拟视图当真实外部执行。

## 后续优先级

1. 新能力构建服务：受隔离的运行环境、无生产凭证默认权限、可复现测试、产物签名与版本回滚。
2. 任务级执行授权：按实际影响检查，而不是限制规划内容；高影响动作显示准确目标、范围及撤回方式。
3. 真实业务任务集评测：分析质量、来源完整性、成功率、人工介入次数、耗时及实际成本。
4. 长期委托：触发条件、持续记忆和主动反馈；数字员工可作为这一层的可选产品入口。

## 本版验证

169 项测试通过，覆盖既有功能与任务流：并发、DAG 验证、未知能力保留、模型自动换路、图片真实结果等待、资料失效、暂停、版本隔离与重启恢复。服务端及离线浏览器验证目标创建、未发送输入保留、设置持久化及 375px 布局。模型、图片和店铺的自动化验证使用模拟服务，不代表客户真实账号联调完成。
