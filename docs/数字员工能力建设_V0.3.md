# 数字员工与能力建设 V0.3

更新：2026-11-06。依据用户提供的《慕雅居AI电商数字员工解决方案 V2.4》§3.2、§3.3、§6.3、§6.7。

## 本次交付的边界

本版将岗位员工、专业能力目录、可执行 Skill、模型连接分开。提供12类岗位模板、134项未去重的规划能力、10个实际可执行的代码 Skill，以及4名默认试点员工。模型驱动执行循环已接入程序，但未使用用户账号做真实模型验证；默认仍为明确标识的规则试运行。

目录中1项标记“已实现限定能力”、10项“部分实现”、123项“规划中”。这是按方案条目记录的覆盖状态，不是已部署134个Agent。与同一Skill关联的条目也不能重复当成已实现能力数量。

## 用户操作与实际结果

| 入口 / 动作 | 前置条件与发生的行为 | 异常和处理 |
| --- | --- | --- |
| 数字员工 → 创建，或点击岗位模板 | 新建员工，填写姓名、岗位、职责、执行方式、模型、Skill及循环上限 | 可以保存未完成配置，但卡片显示缺项，不能加入可执行目标 |
| 数字员工 → 配置员工 → 保存 | 保存新版本；下一次调度读取新配置，已入队调用保存自己的配置快照 | 过期revision拒绝覆盖；重新打开后编辑 |
| 数字员工 → 复制 | 复制配置为新员工，不改原员工 | 副本仍需满足模型和Skill就绪检查 |
| 切换规则试运行 | 不调用模型，按已装配Skill顺序执行 | 文字职责不会变成推理；缺输入返回needs_input |
| 切换模型驱动 | 已测试的模型根据目标和问题选择允许的Skill，再读取结果生成说明 | 未连接、没密钥、未启用本机桥接、测试未通过时阻止运行 |
| 能力中心 → 专业能力目录 | 按岗位、关键词、实现状态筛选134项条目，查看实现范围 | 规划条目没有可执行按钮；部分实现仅提供相关Skill测试 |
| 能力中心 → 可执行Skill → 测试 | 提供虚构样例JSON，可改输入；在后端运行实际规则并生成运行记录 | 缺字段返回具体缺项，不把未知费用写成0 |
| 能力中心 → 模型连接 → 保存、测试 | API或本机Codex两类连接；测试是实际请求，结果保存到模型配置版本 | 修改后清除上次测试状态；失败原因可从运行记录查看 |
| 新建目标 → 数字员工团队 | 选配置就绪的成员、业务类型与范围；创建群聊和成员任务 | 没有就绪员工时不能提交；停用成员不能被新任务调度 |
| 目标 → 资料 | 根据成员能力录入商品/账单；涉及库存、候选比较、保本价时额外显示对应业务表单 | 空金额保持缺失；保存生成新目标版本，旧成果标记已替代 |
| 目标 → 确认计划 | 按已确认成员列表顺序执行，前序成果传给后续员工；模型员工内部自主选Skill | 缺输入停在本步骤；补齐后重新确认计划。执行失败可重试 |
| 群聊 → 指定员工 / @员工 | 对目标当前资料进行一次员工调用，模型收到真实提问和近期上下文 | 规则员工只重跑校验/计算；提问不自动更改事实，不触发发布 |
| 运行记录 → 详情 | 查看输入、结果、配置版本、执行类型及模型/Skill轨迹 | 未授权调用、重复调用、参数覆盖、模型纯文本冒充执行均失败 |
| 暂停 / 恢复 | 停止后续调用；已返回的最终结果可等待恢复再应用 | 暂停发生在模型循环中时，下一步停止；恢复后可能需重试本步骤，已调用的模型额度不会撤销 |
| 交付验收 | 人工确认完成；新团队任务仅交付草案，不执行店铺写入 | 真实发布、调价、广告等接口未接通，不生成虚假成功回执 |

旧版规则目标和模拟发布保留在“旧版规则流程”，用于兼容历史记录。新团队默认仅交付草案。

## 十个可执行 Skill

| ID | 能力 | 限定范围 |
| --- | --- | --- |
| product.validate | 商品资料校验 | 必填字段、数值与确认来源；不证明材质真实或安装兼容 |
| product.draft | 商品草案编排 | 按确认事实组织文字；不执行发布 |
| finance.calculate | 贡献利润核算 | 手工账单计算；上新无账单时只算采购价差 |
| content.outline | 详情页结构草拟 | 文本结构模板，无图片/视频生成 |
| content.review | 宣传声明初筛 | 有限词表与人工核验清单，不是完整合规通过 |
| task.brief | 任务与交付整理 | 汇总目标与当前成果，不做自主跨团队调度 |
| selection.score | 候选商品评分 | 用户提供五项评分；计算加权结果，不自动研究市场 |
| product.compare | 商品参数比较 | 用户提供候选与来源；不抓取竞品，不保证兼容 |
| price.break_even | 单件保本价 | 已知单件费用及平台费率；不覆盖缺失固定费用/税费 |
| inventory.coverage | 库存覆盖 | 输入销量与供应周期估算；不是销量预测或实时库存 |

## 模型接入方式一：个人 ChatGPT 套餐 → 本机 Codex

ChatGPT Plus/Pro订阅不能作为OpenAI API余额，但官方支持用ChatGPT账号登录Codex；官方SDK可以将Codex嵌入个人工作流。本平台实现了这条本机桥接，不提取、上传或分发登录凭证。

在**你自己的电脑**上完成：

1. 安装Node.js 22+，并获取最新项目。
2. 安装官方CLI：`npm install -g @openai/codex`，运行 `codex`，选择 **Sign in with ChatGPT** 登录。使用的是套餐内Codex配额，仍受套餐可用模型与额度限制。
3. 在项目根目录执行 `npm run setup:codex` 安装可选官方SDK（已核对0.166.0，脚本固定该版本）。
4. 复制 `.env.example` 为 `.env`，设置 `ENABLE_CODEX_LOCAL=1` 和自己选择的 `PLATFORM_TOKEN`。不要提交这个文件。
5. 运行 `start-platform.cmd` 或 `bash start-platform.sh`；浏览器只在本机访问服务，输入自己的工作空间令牌。
6. 能力中心 → 模型连接 → 添加 → 选择 **本机Codex · ChatGPT套餐**。模型标识可留空，使用本机Codex默认模型；保存后点击测试。
7. 测试通过后，在员工配置中选择模型驱动和该连接，保存，再试运行或加入目标。

开启桥接时服务器强制只绑定127.0.0.1，并要求工作空间令牌。它不适用于GitHub Pages，也不是把你的个人订阅分享成公共API。后台用官方SDK只读模式生成结构化决定；业务Skill由本平台执行，关闭Codex终端、文件修改、网页、MCP、子代理等功能。模型服务仍需正常网络与有效本地登录。

已验证的是SDK适配契约和本地启用门槛，未使用用户订阅做真实端到端登录测试；不要把配置卡存在当成已接通。SDK原始错误输出不写入平台运行记录，避免混入本地诊断信息。

核对的官方资料：
- <https://github.com/openai/codex#using-codex-with-your-chatgpt-plan>
- <https://github.com/openai/codex/tree/main/sdk/typescript>

## 模型接入方式二：兼容 OpenAI 的 API

配置完整Chat Completions HTTPS地址、模型ID、服务器密钥变量名（`MODEL_SECRET_`前缀）。密钥值只放在服务器环境。`AGENT_ALLOWED_HOSTS`加入接口域名；云环境网络策略也需允许对应域名。连接测试通过后才能给模型员工使用。

单轮响应上限256KB，不允许重定向，不访问私网。模型调用只暴露员工已装配的Skill，无任意URL、代码执行或业务写入工具。调用参数不允许覆盖用户保存的事实。每个Skill单次任务最多执行一次，最多8轮模型调用。

本机Codex每轮使用完整消息上下文发起结构化决定，不承诺与这里的聊天历史同步；平台保存的是业务消息、Skill结果和运行轨迹。

## 数据与接口

`.data/platform.json`继续使用schemaVersion 1，升级时补充 `employees`、`models`，保留既有目标、配置和运行记录。默认数据目录不提交Git。

| API | 功能 |
| --- | --- |
| GET /api/workforce | 岗位、目录、Skill、员工就绪状态和模型连接 |
| POST /api/employees | 创建员工 |
| PUT /api/employees/:id | 按revision更新员工 |
| POST /api/employees/:id/test | 队列中试运行已保存的员工配置 |
| POST /api/models、PUT /api/models/:id | 新建/修改模型连接；不接收密钥值 |
| POST /api/models/:id/test | 实际连接测试，结果绑定revision |
| POST /api/skills/:id/test | 测试Skill输入；不执行写入 |
| POST /api/goals | `employeeIds`表示新团队，旧`members`仍兼容 |
| POST /api/goals/:id/actions | 团队支持计划、资料、补充业务输入、消息、暂停、重试、验收 |
