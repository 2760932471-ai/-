# V0.11 群内协作交接

## 本次解决的问题

旧版只创建目标与群，然后提示负责人填写资料。选品目标没有匹配研究、选品员工，正式执行时也只显示统筹通知；协调员工的摘要只有前序成果标题，用户无法判断员工是否真正用了彼此的结果。

V0.11 让创建后的输入检查、待补资料、任务接收、正式交付和成果交接进入同一个讨论区。基础模式仍为真实代码执行，不把本地检查包装成模型自由讨论。

## 用户操作与结果

1. 点击“新建目标”，输入“寻找市面上性价比高的淋浴头”。下一步按选品关键词推荐市场研究、选品规划和运营协调员工；范围默认“待比较候选”，不再填角阀 SKU。用户手动指定的成员仍优先。
2. 创建后自动运行本地输入检查，在群内展示每位员工可用能力、缺失资料及交接顺序。此时没有调用模型、外部服务，也没有正式交付物。
3. 没有候选资料时显示需要 2–50 个有来源的候选。点击“补充业务资料”打开当前表单，表单支持录入两款候选的参数、价格、来源和五项评分；底层接口最多接收 50 款。资料保存生成新版本并重新检查，不自动执行。
4. 回到讨论，点击“确认分工并开始”。若还有缺项，按钮明确显示“按当前资料开始执行”，运行到缺少输入的员工时会停止；不会代填缺失资料。
5. 市场研究员工交付参数比较；选品员工收到该比较正文并生成加权评分；运营协调员工收到本轮正式成果正文，整理有来源的摘要。每一步在群里显示接收与交付记录，链接打开相应完整成果。后续步骤共享的是持久化的交付物，不是仅在界面模拟发言。
6. 全部执行成功进入“待验收”，负责人查看交付物后验收。执行没有触发真实发布、采购、调价或投放。

### 已有目标如何继续

待确认的旧选品目标，如果当前成员缺少研究或选品岗位，讨论底部显示“改用研究 → 选品 → 协调团队”。点击后更新执行成员、任务、版本和默认示例范围，保留旧讨论、资料与讨论成员，并重新检查。

其他旧团队目标可点击“检查分工与资料”启用群内交接记录。已经执行的目标不会被静默重排。

## 异常与一致性

- **资料不足 / 调用失败**：停在当前员工，保留已完成结果，不启动后续员工；补齐资料后确认新版本，或重试当前步骤。
- **暂停**：未启动工作保持排队；已在执行的调用按现有机制保留返回结果，恢复后再应用。不会在暂停期间继续交接。
- **修改资料**：版本递增，旧草案保留为历史；旧任务结果不能写入新版本。
- **修改员工能力**：已有检查失效。点击“重新检查”后才能确认执行；员工停用会明确列出配置缺口。保存业务资料、继续聊天不依赖员工配置就绪。
- **重复点击**：同一创建请求返回原目标，同版本、同配置的检查不重复刷消息；已确认的计划不能再次确认。
- **刷新 / 重启**：服务端模式保存到平台 JSON 数据文件；免安装预览保存在当前浏览器。两种模式不互相同步。

## 技术实现与边界

- 沿用单员工执行循环和队列，总控串行传递 `observations`。新增成果 ID、员工名称、运行 ID 与版本用于交接追踪。
- `startCollaboration: true` 使新团队目标创建后自动检查，并将协调岗位排在最后。内容快捷入口保持原有直接生成行为。
- `kickoff`、`regroupSelection` 使用现有 `goals/:id/actions` 接口，要求 `expectedVersion`。本地预览复用同一实现。
- 选品能力基于用户提供的候选与评分。五项评分为需求、竞争优势、利润、供货、风险可控性，均为 0–100，越高越好；不等于模型验证的市场事实。
- 没有新增全网搜索或 1688 抓取。供应商注册不代表已授权接通；供应商和知识库接入沿用 AI基础能力配置与知识库入口。导入素材也不会自动转为已核验的候选评分。
- 没有配置真实模型时，不会使用 ChatGPT 订阅额度生成自由对话。模型连接与外部工具仍按现有连接、测试及能力装配要求使用。

## 验证

自动测试覆盖：选品推荐、无数据时不编造结果、创建与检查幂等、消息持久化、真实成果逐步传递与汇总、旧目标重组、版本冲突、暂停、配置变更。

浏览器脚本 `scripts/check-collaboration.mjs` 覆盖自然语言新建、候选表单保存、群内执行、完整交付物预览、刷新恢复以及 390 / 768 像素布局；支持 `--offline` 验证生成的免安装 HTML。已有内容制作、输入框 @ 和旧会话兼容由 `scripts/check-ui.mjs` 回归。

本次验收：97 项自动测试通过；服务端与免安装预览的协作端到端检查通过；离线内容制作、输入框 @、全体提及、旧会话及移动端回归通过。
