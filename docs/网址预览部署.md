# 把交互预览部署为网址：GitHub Pages

这条路线发布免安装预览：打开网址即可体验新建目标、群聊、Agent 配置和内置代码计算。GitHub Pages 不运行 Node 后端，不能承载服务器密钥、真实 HTTP Agent 或多人共享数据。页面数据只存访问者自己的浏览器；公开网址的访问者都能看到演示界面。

## 一次性开启

发布内容准备在仓库的 `gh-pages` 分支，只有 `index.html` 和 `.nojekyll` 两个文件。应用源码、项目交接、账单、聊天数据与密钥不在这个分支中。

1. 登录有该仓库管理权限的 GitHub 账号，打开 <https://github.com/2760932471-ai/-/settings/pages>。
2. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
3. 在 **Branch** 选择 **gh-pages**；文件夹选择 **/ (root)**；点击 **Save**。
4. 等待 GitHub 构建完成。成功后，此设置页会显示 **Your site is live at ...** 和 **Visit site**。以该链接为准。

没有自定义域名时，预期地址为 `https://2760932471-ai.github.io/-/`。保存分支文件不等于站点已发布；在设置页显示成功前，地址可能返回 404。

通常需要等待几分钟。若未成功，查看仓库 **Actions** 中的 `pages build and deployment` 任务及其错误，而不是反复修改代码或保存配置。

如果看不到 gh-pages，先刷新设置页。如果 Pages 页面提示账号/私有仓库套餐不支持，不要为了预览擅自把整个仓库公开；需要选择支持当前仓库的方案或其他静态托管服务。

## 后续更新页面

先在 main 分支修改 UI 或 Agent 代码并完成验证，然后运行：

```sh
npm run deploy:preview
```

脚本使用当前 Git 身份，生成最新单文件 HTML，只把两个发布文件推送到 `gh-pages`。不切换工作分支、不上传运行数据、不强制覆盖远端历史。如果发现发布分支有其他文件或并发更新，将停止并提示。

开启 Pages 后，该分支的新提交会触发站点更新。构建是否成功仍以 GitHub Actions 和 Pages 设置页为准。

## 真正的前后端网址

当需要真实外部 Agent 或多设备共用数据时，应使用能运行 Node.js 22+ 的服务或服务器：执行 `npm start`、配置 HTTPS、设置 `PLATFORM_TOKEN`、将 `DATA_DIR` 放在持久化磁盘中，并配置 Agent 域名和密钥。当前 JSON 存储只支持单进程，不应直接扩容为多实例。
