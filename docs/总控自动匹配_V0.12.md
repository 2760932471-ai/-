# V0.12 总控自动匹配成员

## 交互变化

新建目标默认选择“总控自动匹配”。用户填写目标和业务范围即可，成员列表默认收起；实际团队在后台根据最新的员工配置安排，页面传来的默认勾选不再决定执行团队。选择“我来指定成员”后才展开列表。

目标创建后，群里显示“总控自动安排”、实际成员、交接顺序及“为什么选择这些成员”。点击理由可查看每位员工承担的能力与配置就绪依据。选择团队不需要用户确认，正式执行仍通过当前计划确认按钮启动。

例如“寻找市面上性价比高的淋浴头”，当前默认能力匹配为：

1. 市场研究数字员工：比较已有候选的参数、价格与来源。
2. 选品规划数字员工：基于有依据的输入评分计算排序，仅调用评分能力，不重复执行参数比较。
3. 运营协调数字员工：接收比较与评分的真实正文，汇总交付。

若研究员工不可用，但其他就绪员工已装配参数比较，总控可将该能力分配给他；不会仅因岗位名称合适就选择没有能力的员工。

## 自动匹配规则

- 根据已支持的目标关键词拆出所需能力，覆盖选品、上新、标题、卖点、详情文案、视频脚本、主图简报、核算、促销、库存、推广、客服与宣传初筛。简单否定片段如“不要视频”不作为需求。
- 只选择启用、已装配所需 Skill、模型及外部能力配置就绪的员工。模型员工仍须对应连接版本测试通过。
- 优先选择无关能力更少、能力组合更专一的员工，再考虑复用已选成员；同分用稳定 ID 决定。不是基于未经测量的“智能程度”或历史业绩排名。
- 已有内置业务工作包需要的代码员工尚未装配时，总控可安装相应本地只读工作包。已存在但停用或待配置的工作包不会被自动重启。
- 正式分工只包含本次匹配到的 Skill；未分配能力不随员工自动运行。最多 8 位执行员工。
- 不理解目标、找不到就绪员工或超过团队上限时，显示具体缺口并阻止确认执行。用户可补充目标说明或配置能力，不会用无关员工伪装完成。

这是本地规则能力匹配，不会调用大模型进行任意语义推理，不会自动接入 ChatGPT 订阅额度。选品仍需候选来源与资料，主图能力仍交付设计简报，未新增全网搜索、1688 抓取或真实图片生成。

## 旧目标与变更

- 加载旧数据时，对没有成员安排标记、尚在计划阶段、没有已采用或待审自定义分工的团队目标自动匹配。截图中的错误上新团队在此范围内。
- 旧讨论、业务资料及交付历史保留。替换执行成员不删除历史消息；原成员仍可参与讨论。讨论成员上限 24 人，满员时优先保留新执行成员。
- 已有手动选择标记、自定义分工、内容快捷任务、执行中及已结束的目标保持原流程。
- 自动团队在计划阶段发现员工配置变化时重新匹配；未改变实际安排则不重复刷消息或升级计划。
- 资料更新仍产生新版本；旧任务结果不会写入新版本。员工已经开始执行时不悄悄改组。

## 手动调整与异常

“调整成员”打开目标与成员安排弹窗，可以补充目标说明、切回自动或指定 1–8 位成员。手动保存后总控不自动替换，刷新与重启也保留此选择。弹窗使用打开时的目标版本，期间发生变更会提示冲突，不覆盖新计划。

自动团队有能力缺口时，“补充目标 / 调整成员”可以继续完善说明；缺口与业务数据缺失分别展示。能力完整不等于资料齐全，输入检查与真实执行仍可能要求补充数据或来源。

## 接口与验证

- 新建团队目标：`teamSelection: "auto"`；后台独立匹配，允许不提供 `employeeIds`。旧 API 显式提供成员且不传此标记时保留手动行为。
- 手动调整：`goals/:id/actions`，`kind: "setTeam"`、`expectedVersion`、`teamSelection`，可附 `text` 与手动 `employeeIds`。
- 新增 `src/workforce/matching.js`，服务器和单文件预览共用实现。
- `test/matching.test.js` 覆盖能力匹配、无效模型排除、执行子集、旧目标迁移幂等、动态替换、手动保护、已执行任务保护与未知目标澄清。
- `scripts/check-auto-team.mjs` 在浏览器注入旧版目标，验证加载即匹配、理由展示、重复刷新、手动覆盖、目标变更与手机弹窗。
