# V0.16 企业知识、统一选择菜单与图片生成

## 本次问题与原因

用户导出的目标对话（2026-11-10）是“寻找合适的产品，并制作商品详情页图片”。其中实际检索结果是 0 份知识文档、0 项可用来源，网络搜索 / 供应商连接也未启用。总控分配的主图策划员只装配 `copy.image_brief`，产出文字简报，不调用图片模型。以此配置无法完成选品或生成真实商品图片。

V0.14 提供的文档主要是操作指引，适合作业规范参考，不是企业商品、供货或售后事实。新资料不覆盖用户已经入库的旧文档，旧入门包作为历史保留。

可导入文件在 `deliverables/企业知识资料_V0.16/`，支持逐篇 Markdown 上传。应用内选择资料后会先进入文档编辑表单，并带入来源；用户核对后保存、切片。三个待补台账的“启用”默认未勾选，补齐实际资料并核验后再启用。不存在的企业事实不会被自动补写。

知识描述“是什么、有哪些事实与条款”；Skill 实现“如何执行某个动作”。知识被检索引用，Skill 则运行代码或工具。这次资料没有把选人、调度或执行步骤当作企业事实。

## 统一选择菜单

全站单选下拉使用同一组件：包括内容渠道、视频时长、模型配置、岗位、知识库范围、店铺关联及图片比例。原始 select 保留表单字段、原有 change 逻辑和约束校验，屏幕展示为自定义菜单。

- 黑白灰和蓝色选中状态，菜单白底、圆角、统一间距。
- 鼠标 / 触摸选择，方向键移动，Enter 确认，Escape 只关闭菜单，Tab 返回正常焦点顺序。
- 菜单跟随控件位置，根据上下空间展开；弹窗内放在同一顶层，避免被遮挡。
- 禁用、空选项、必填校验和动态更新仍生效；手机菜单不超出屏幕。
- 商品标题、卖点等非视频表单不再显示“脚本时长”。

## 图片制作的实际交互

入口一：工作应用 → 生成主图 / 详情图。
入口二：目标包含“主图 / 图片 / 详情图”等内容时，协作群中显示“生成图片”。从群内发起会关联该目标，图片成功后写入交付物并发送带链接的交付消息。

1. 选择“文字生成”或“参考商品图生成”。文字生成不要求底图，明确为概念图，不证明在售 SKU 的外观。参考方式从已审核、已授权且未过期的知识 / 内容来源或供应商素材记录中选择图片。
2. 描述商品及画面，选择方形主图、竖版详情模块或横版场景图。当前单次生成一张，不自动生成整张无限长详情页。
3. 系统默认按描述检索启用知识库（群内沿用目标知识范围），最多采用 4 个 BM25 命中片段，保留文档标题、版本、切片号。没有相关知识仍可生成概念图，但不添加未提供的企业与商品事实。相关片段及选定图片会发送给所配置的图片服务。
4. 用户确认用途与服务用量后，后台建立持久化任务。相同请求 ID 重复提交只创建一次；同 ID 改内容被拒绝。
5. 后台调用 `/images/generations` 或 `/images/edits`。已有参考图可编辑背景和构图；结果仍需人工核对结构、颜色、标志、配件等实物一致性，模型无法提供绝对保真保证。
6. 成功后校验 PNG 头部与尺寸，文件保存在当前工作空间的 `generated-images/`，任务只保存元数据，不把图片大段 Base64 塞进所有目标响应。查看 / 下载接口通过工作空间访问令牌鉴权。
7. 工作应用中点击“查看图片与下载”，预览 PNG，再下载。刷新、重新进入工作空间后任务与文件仍在；关联目标中的交付物也可直接打开图片。

## 配置生图服务

入口：AI基础能力配置 → 图片生成。

使用兼容 OpenAI Images 的服务，默认 API 根地址 `https://api.openai.com/v1`，默认模型 `gpt-image-1`。服务须支持 `quality=medium`、`output_format=png` 与 Base64 的 `b64_json` 返回。本版不自动下载服务返回的任意图片 URL；只有 URL 而无 `b64_json` 的服务暂不兼容。

服务器环境变量示例（值不要提交 Git，不要发聊天）：

```dotenv
PLATFORM_TOKEN=你的管理员访问令牌
IMAGE_SECRET_PRIMARY=独立图片API密钥
AGENT_ALLOWED_HOSTS=api.openai.com
```

如果已有模型、店铺、供应商域名，需要合并保留；编辑参考图还需允许图片 CDN 域名。云环境出站策略也需放行对应域名。使用 `node --env-file=.env src/server.js` 启动，网页输入管理员令牌后，配置中填写变量名 `IMAGE_SECRET_PRIMARY` 并启用。

ChatGPT Plus / Pro 订阅、本机 Codex 登录与图片 API 是不同调用通道。本版不能将聊天订阅自动转成服务器图片 API 额度。GitHub Pages / 免安装 HTML 没有后台凭证和图片执行器，会明确提示未连接，不生成伪造图片。

“已配置”只表示当前环境有凭证和启用配置，首次真实出图才验证模型权限、额度和协议兼容性。当前开发环境没有图片密钥，实际服务联调仍待用户配置。

## 失败与恢复

| 情况 | 处理 |
| --- | --- |
| 没有可用图片服务 | 留在表单提示配置入口，不创建假成功任务 |
| 参考图未审核、无授权、过期或已停用 | 提交前拒绝；执行及下载时再次检查 |
| 知识版本 / 参考图 / 目标 / 生图配置变化 | 执行前停止，调用期间变更则不把结果交给旧版本目标 |
| 平台明确返回 4xx | 记录失败及 HTTP 状态，不暴露完整响应或密钥 |
| 超时、网络中断、5xx、响应无法确认 | 标记结果未确认，不自动重试；可能已计费，需要核对服务端记录 |
| 服务重启时任务正在生成 | 恢复为结果未确认，不再次发送请求 |
| 任务已排队但尚未开始 | 重启后可以正常开始；最多 10 项排队 / 运行中任务，每空间一次处理一项 |
| 响应不是合法 PNG / 超过响应上限 | 不交付成功图片；只保存安全错误说明 |

使用 `src/images.js` 管理任务，`src/image-transport.js` 实现图片服务协议和文件读写。图片在独立任务队列处理，不阻塞群聊 / 普通员工队列。当前不提供生图任务自动重试、取消远端请求、自动合成长图、从任意供应商网页绕过授权抓取图片，或自动将生成图片上架。
