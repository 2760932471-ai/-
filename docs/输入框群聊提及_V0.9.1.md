# V0.9.1 输入框内群聊提及

## 正常聊天

直接在“协同工作台 → 讨论”的消息输入框键入 `@` 或 `＠`。候选列表贴着输入框出现，不打开独立选人弹窗，也不要求先选上方接收者。

- 第一个候选是 **所有员工**，注明当前群内可回复人数。后续先列本群员工，再列可邀请的其他员工。可继续输入姓名或岗位过滤。
- 点击候选或用方向键 + Enter 确认，在正文插入 `@员工姓名 `，然后继续写消息。选人时不发送；普通 Enter 发送，Shift + Enter 换行，输入法确认键不发送。
- `请@客服售后数字员工…` 支持中文紧贴；鼠标移动输入光标后可在句中插入。删除正文中的提及即删除此次通知，不保留隐藏的全体选中状态。
- 输入框底部小 `@` 只是插入字符、展开同一候选列表的快捷键。原“发送给 / 消息用途 / 暂停回复”移入下方折叠的“消息设置”，无需使用它们即可定向聊天。
- 浮层挂载到页面顶层、随输入框和可视区域定位，避免被工作台容器裁切；手机同样直接点击候选。点击其他区域、离开输入框、切换目标会收起候选。

## @所有员工

“所有”指 **当前目标协作群内的员工**，不指整个平台。支持正文中直接输入 `@所有员工`、`@所有人`、`@全体成员`、`@all`，其中英文别名须以空白或标点结束。

提交时后端根据当前成员、启用及配置就绪状态确定收件名单，记录在该条消息的 `targets` 中。每位就绪员工排一个回复任务，逐位处理；正文下显示“已通知本群 N 位员工”。不可用员工记录为 `skippedTargets` 并显示跳过人数。提交后新加入的成员不会补收此前广播。

只点名个人时仍最多 4 位；全体通知支持群内全部就绪成员（讨论群最多 24 位）。同时写全体和某位员工时按 ID 去重，不重复回复。明确选择群外员工时仍可随消息加入讨论，不改变执行计划、业务授权或版本。

### 异常与边界

| 条件 | 行为 |
| --- | --- |
| 本群没有就绪员工 | 不保存或排队，提示先邀请或启用员工 |
| 待回复队列容量不足（最多 24 条） | 整条消息原子拒绝，不出现只通知一部分却显示全体成功 |
| 回复已暂停 | 保存消息与完整队列，恢复后逐位回复 |
| 排队后员工停用或模型失效 | 保留消息，按现有调度逻辑显示不可用或调用失败，不声称已成功回复 |
| 员工缺业务资料 | 回复待补项；全体通知不绕过资料校验 |
| 开始新话题 / 上下文变更 | 按已有上下文版本规则处理旧队列与运行结果 |
| 删除 `@所有员工` 后仅点名个人 | 只发送给正文中的个人，后端不信任隐含的全体标记 |

全体提及保留名不能用于新建 / 重命名员工。现有基础代码员工仍按所装配能力处理；提及功能不代表已接通通用模型自由对话。

## 验证

`npm run check` 和 `npm test`：92 项通过。新增全体快照、超过 4 人、跳过不可用员工、去重、暂停、队列溢出、保留名及全体文字删除回归。

`scripts/check-ui.mjs` 在服务器 HTTP 版与断网预览中，直接从输入框完成个人和全体提及；不使用辅助按钮或接收者设置。检查手机浮层完整可见、收到每位成员回复、删除全体文字后只通知个人、IME Enter、旧会话及原内容制作流程。静态预览沿用存储 key，无需重置数据。
