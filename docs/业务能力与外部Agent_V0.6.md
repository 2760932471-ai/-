# 业务工作包与外部 Agent · V0.6

更新：2026-11-06。新增 4 个业务代码 Skill，加上原有 10 个，共 14 个本地可执行 Skill。12 类岗位 / 134 项能力仍是规划目录，不能据此宣称全部已实现。

## 1. 从目标到交付的交互

1. 点击侧栏 **新建目标**，输入“查清本月哪些 SKU 亏损”。点击 **按目标装配并推荐员工**，系统按关键词匹配盈亏工作包，幂等创建对应员工并选中。用户可修改成员；未匹配时保留手动选择。这个推荐目前不调用模型，不是完整自主经营规划。
2. 确认范围并创建目标，进入 **资料**。根据成员挂载的 Skill 展示账单、活动成本、补货参数或客户问题表单。可以下载 CSV 表头、上传 UTF-8 CSV 或直接粘贴；“填入演示数据”使用明确标注的虚构数据。
3. 填写数据来源与期间，点击保存。保存按目标版本校验，其他页面已修改时提示重新加载；不会覆盖新版本。保存后需重新确认计划。
4. 确认计划后按已选成员顺序执行。缺字段、格式错误、无政策证据时返回待补资料；不会把缺失成本当作 0。补齐后重新确认并执行。
5. 在 **交付物** 查看实际计算报告，在 **运行记录** 查看输入快照、配置版本、每步结果。群聊可以继续提问或指定员工；协调入口会根据已有成员的业务能力匹配处理人，不会擅自增加外部员工。

也可以从 **能力中心 → 业务工作包 / 外部 Agent** 开始。点击“先用样例试运行”只测试虚构输入，不创建业务目标；点击“装配员工并创建目标”打开已选相应员工的新建入口。重复装配返回原员工，不重置用户的修改。

本地代码不消耗模型额度。员工可配置为按顺序执行 Skill，或在已有模型连接验证通过后，由单 Agent 的有上限循环选择已挂载的代码 / 外部能力。团队调度仍按确认顺序执行，不是自主跨岗位规划。

## 2. 四个工作包的真实能力

### SKU 盈亏诊断：commerce.sku_profit

输入 `commerce = {csv, source, period}`。CSV 表头：

```csv
sku,netSales,goods,fees,fulfillment,ads,returns,other
DEMO-A,10000,4000,500,800,2500,200,100
DEMO-B,3000,1600,150,400,1200,200,50
```

以上是虚构样例。金额统一为人民币元；净销售额已扣退款本金，允许负数。其余列依次为货品成本、平台费用、履约、广告、额外售后损失、其他费用，均非负。`returns` 不得再次填写已经扣过的退款本金。每行按分四舍五入后汇总，同 SKU 的多行相加；用户应避免重复导出。

贡献利润 = 净销售额 − 所列费用。输出按利润排序的 SKU、贡献率、广告前贡献及核对建议。净销售额非正时不算利润率。样例 A 为 1900、B 为 -600、合计 1300；A 净销售额改为 12000 后合计 3300。未纳入未录入税费和固定费用，不能当作会计净利润。

### 促销折扣测算：campaign.discount

输入 `campaign`：`price` 原价、`goods` 货品成本、`fulfillment` 履约、`adsPerOrder` 单件广告、`returnCost` 单件售后、`other` 单件其他成本、`feeRate` 平台百分费率、`volume` 假定整数销量、`fixedBudget` 活动固定预算、`discountRates` 折扣率数组、`source` 假设来源。

20 表示降价 20%（八折）。允许 1–12 个 0–90% 折扣；售价大于 0 且不超过 1000 万，销量为 1–100 万整数，费率低于 100%。实付价和单件贡献按分四舍五入。单件贡献 = 实付价 × (1 − 费率) − 单件费用；活动贡献 = 单件贡献 × 假定销量 − 固定预算。

输出每个折扣的实付价、单件贡献、活动贡献、保本销量，及按给定销量分摊预算后的保本价。单件贡献负数，或贡献为 0 但预算大于 0 时，不能靠增加销量保本；两者均为 0 时保本销量为 0。所有情景采用同一假定销量，未预测促销销量增长，也未修改店铺售价。

### 批量补货：inventory.replenish

输入 `replenishment = {csv, source, period}`。表头：

```csv
sku,stock,inbound,dailySales,leadDays,safetyDays,reviewDays,moq,packSize
DEMO-A,20,10,5,7,3,7,20,12
```

依次为现货、在途、日销、交期天数、安全天数、复核周期、最小采购量、整箱量。SKU 不得重复；现货、在途、MOQ、箱规为整数，箱规至少 1。

目标库存 = 向上取整(日销 × (交期 + 安全天数 + 复核周期))；扣现货与在途后若仍有缺口，按 MOQ 和箱规向上取整。本例目标 85，缺口 55，建议 60。现货不足以覆盖交期时标记风险；零日销不自动补货。在途假定在目标周期内到货，用户必须核验 ETA。未预测季节变化、未创建采购单。

CSV 通用限制：1–200 条记录、80,000 字符、文件不超过 256 KB，UTF-8；支持 BOM、带引号的逗号和换行。拒绝重复表头、列数不匹配、空必填字段及非数值。普通数值上限 10 亿，避免无限值参与计算。Excel 文件需先导出 CSV。

### 售后证据答复：service.evidence

输入客户问题 `serviceQuestion` 或群聊 `question`；目标勾选的知识库生成本轮 `knowledgeRecall.hits`。按词项匹配选取最多 3 个片段，交付政策原文、文档版本 / 切片引用、确认话术与人工核对项。

没有客户问题或匹配证据时返回待补资料；资料被更新 / 撤回后，旧引用会被现有版本校验阻止继续使用。此 Skill 是证据摘录与确认话术，不是模型的语义推理。冲突政策需要人工判断，不自动认定退款资格，不向消费者发送消息。

## 3. 外部 Agent 接入流程

入口：**能力中心 → 业务工作包 / 外部 Agent → 接入外部 Agent**。

1. 在自己的 Dify 工作空间发布只读 Workflow，或准备兼容本节 JSON 协议的 HTTP 服务。平台尚未替用户创建或发布任何 Dify 应用。两份可照着配置的蓝图：[商品内容 Agent](agents/Dify商品内容Agent.md)、[售后政策 Agent](agents/Dify售后政策Agent.md)。
2. 在平台服务器 `.env` 保存密钥值和授权域名，重启服务。界面只填变量名，不能填密钥值。

```dotenv
EXTERNAL_SECRET_DIFY=replace-on-your-server
# 与已有模型、知识库和素材域名合并，不能直接覆盖旧配置
AGENT_ALLOWED_HOSTS=api.dify.ai
```

自建 Dify 改为自己的公网 HTTPS 域名。默认拒绝内网地址、域名未授权、重定向；不能以此接口调用本机任意服务。

3. 配置名称、职责、协议、完整 URL、密钥变量名、超时、允许发送的字段，并核验远程应用确实只读。Dify 地址例如 `https://api.dify.ai/v1/workflows/run`，输出字段默认 `result`；超时 1–120 秒。接口不能包含查询参数或 URL 凭据。
4. 逐项选择允许外发的数据，默认只选目标、范围、商品事实和方案；账单、知识库全文片段等需明确勾选。售后蓝图需要 `question` / `serviceQuestion` 与 `knowledgeRecall`。未选字段不会发送。
5. 保存后显示“待测试”。点击试运行，填写协议测试 JSON，查看结构化输出。缺密钥、超时、网络拒绝或格式错误会失败；不会伪装成演示成功。`needs_input` 代表协议可用但业务资料不足，可通过协议测试，不代表业务任务完成。
6. 测试成功后，到 **数字员工 → 配置** 勾选该外部能力。与本地 Skill 一样，可以被顺序执行或被已接通模型的员工循环选用。
7. 修改任何外部配置会增加版本并清除测试结果。未启用、无密钥或当前版本未测试均阻止任务执行。运行快照绑定配置版本；执行中改版 / 停用后不会把旧响应当作新配置结果。

只读勾选是管理员的声明，协议测试也仅验证可调用和输出结构，不能证明远程应用内部没有副作用或内容一定正确。应先审阅自己部署的节点与工具，再接入有业务影响的环境。当前平台仅接收交付物，不根据远程响应执行发布、采购、退款或发送消息。

## 4. 接口协议

通用 HTTP 请求：`POST`，`Authorization: Bearer <服务器变量值>`，`Content-Type: application/json`。

```json
{
  "schemaVersion": 1,
  "skillId": "external_generated_id",
  "configVersion": 1,
  "input": {"goal": "基于已确认参数准备标题", "facts": {}}
}
```

通用响应（Dify 的 `result` 也必须是这个对象，或编码为 JSON 的字符串）：

```json
{
  "status": "needs_input",
  "summary": "缺少已确认的商品参数",
  "missing": ["商品名称与可核验参数"],
  "artifacts": [],
  "metrics": {}
}
```

完成时 `status` 为 `succeeded`，至少提供一个 `artifacts`：`{"title":"商品草案","body":"正文","evidence":"事实或政策来源"}`。只接受这两种业务状态；运行失败由平台记录。summary 最多 6000 字，missing 最多 30 项，每项 500 字；交付物最多 8 个，title / body / evidence 分别最多 200 / 30000 / 2000 字。响应总大小上限 256 KB。凭据回显响应被拒绝，错误响应正文不保存。

Dify 请求使用：

```json
{
  "inputs": {"context": "{\"goal\":\"准备商品内容\"}"},
  "response_mode": "blocking",
  "user": "ai-workbench"
}
```

Start 节点必须提供字符串 `context`；End 节点返回 `result`。平台检查 `data.status === "succeeded"`，再校验 `data.outputs.result`。保存工作流运行 ID 方便排查。当前适配 Workflow blocking，不是 Chatflow、流式聊天或任意平台私有协议。官方接口实现参考：[Dify workflow.py](https://github.com/langgenius/dify/blob/main/api/controllers/service_api/app/workflow.py)。第三方服务还需独立验证其质量、授权和成本；ChatGPT Plus / Pro 不能作为 Dify 云模型的 API 密钥。

平台管理 API：

- `POST /api/workforce/recommend`：`{text}`，返回关键词匹配及已就绪成员。
- `POST /api/workforce/install`：`{recipeId}`，装配业务包，重复调用返回原员工。
- `POST /api/external-skills`：创建；`PUT /api/external-skills/:id`：带当前 revision 更新。
- `POST /api/external-skills/:id/test`：`{input}`，返回队列运行 ID；沿用运行记录查询。
- 员工配置的 `skillIds` 可同时包含代码能力与 `external_...` 能力。

## 5. 验证与边界

自动化覆盖计算、CSV 格式与缺项、知识引用、装配幂等、目标调度、外部字段白名单、Dify / HTTP 协议、测试门槛、配置失效和模型循环选择外部 Skill。传输测试使用受控服务响应，没有客户 Dify / 模型真实凭据联调。

GitHub Pages / 单文件 HTML 只能体验本地代码工作包和接入配置交互，不能调用外部 Agent。服务器版才能读取环境变量并联网。完整产品仍采用单工作空间 JSON 存储；134 项规划能力、完整业务系统连接、生产权限和自主总控尚未全部实现。
