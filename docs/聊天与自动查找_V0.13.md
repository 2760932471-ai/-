# V0.13 聊天与自动查找

本版针对真实会话中反复要求补资料、追问却返回整段方案的问题修复。当前仍是本地规则与代码能力；接入模型后可以调用已装配能力。ChatGPT 订阅额度不会自动成为后台 API 配额。

## 聊天交互

- 工作台按可用视口高度布局，聊天记录独立滚动。压缩顶部栏和状态栏，输入框默认一行，随输入增长至 120px 后内部滚动。协作进度默认折叠，展开后确认计划、查看分工或重试查找。
- 每条用户、员工和总控消息下方用回箭头图标引用；鼠标提示与读屏标签均为“引用回复”。点击后输入框上方显示引用摘要，可取消；发送后保留引用关系。
- 不再显示固定、排除、手动设置上下文的入口。系统保留当前目标、阶段、实际阻塞、近期用户要求及引用关系，过滤重复员工回复和检查/交接噪声，按消息数与字符预算筛选。历史手动设置保留兼容，旧数据不被清空。
- 这是有上限的规则筛选，不是无限记忆或模型摘要。最近约束优先，但不会把聊天内容直接覆盖已确认的商品事实。

## 选品资料查找

1. 新建目标后总控匹配适合成员，检查目标范围内启用的知识库和可用供应商文档；缺数据且有启用的 HTTP 来源时自动发起只读同步。确认执行计划仍由负责人完成。
2. 用户问“为什么要补资料”“你自己去找”或追问“？”时，总控回复实际查找范围、找到的商品与仍缺什么，不再调用任务摘要或粘贴整份方案。
3. 只说“自动选品”时询问品类，可附预算；例如“找淋浴头，预算50元以内”。系统从已有资料查找候选，用户不必录入候选商品与五项评分。
4. 解析知识文档或已核验供应商文档中的 Markdown 表格、CSV、JSON 数组及字段行。商品至少需要 SKU/型号和有效正数报价；保留来源及文档版本。参数不详标记未知，设计方案文字不等于真实报价。
5. 找到至少两个合格候选后，员工按分工交接参数比较、报价初筛及汇总。只有报价时按价格排序，明确不能据此认定综合性价比；质量、销量、运费、起订量等未知项不编造。
6. 每轮执行共享首次实际调度时的候选快照。后续聊天可以查找新条件，但不会让不同员工使用不同版本候选；修改执行范围需回到计划阶段重新确认。手工输入的候选仍优先。

可导入的最小 CSV 示例（仅为格式示意，不是真实报价）：

```csv
SKU,商品名称,报价,材质,接口
DEMO-A,淋浴头 A,39,ABS,G1/2
DEMO-B,淋浴头 B,49,不锈钢,G1/2
```

## 状态与异常

| 情况 | 行为 |
| --- | --- |
| 无品类 | 询问目标条件，不要求客户搜集整套商品资料 |
| 无来源或零条报价 | 说明已检索范围和真实缺口，提供知识库、供应商接入入口 |
| 只有一个候选 | 展示已发现记录；不伪造第二个进行比较 |
| HTTP 新增或变更记录 | 保留待核验状态，核验前不用于结论 |
| 同步失败 | 说明接口/授权问题；五分钟内自动请求去重；主动点击查找可重试 |
| 来源停用、到期、撤销或文档更新 | 执行和验收时拒绝使用过期证据，要求重新安排本轮计划 |
| 查找时目标版本/话题改变 | 不把旧请求结果用于新目标 |
| 回复暂停 | 保留待回复请求，恢复后继续；避免丢失回复 |
| 待输入且找到了合格候选 | 继续已确认计划；不跳过计划确认或成果验收 |

自动同步每轮最多检查三个已启用 HTTP 来源。接口传输继续使用现有域名限制、超时与数据校验。导入资料来源与真实性仍需业务核验。

## 预览与完整后端区别

免安装 HTML 可运行本地知识检索、自动候选提取、报价比较、消息存储与员工交接；数据保存在当前浏览器。HTTP 同步、真实模型与外部 Agent 需要完整后端和有效配置。

本版没有接通全网搜索或 1688 账号/API。不会把“查找来源”写成已经搜索全网；供应商自动同步仅对已配置的授权接口生效。

- 浏览器脚本：`scripts/check-chat-experience.mjs` 覆盖引用图标、自动上下文入口、三种屏幕尺寸、知识库导入、自然语言筛选、实际员工交付。
- 原有内容制作、中文/全角 @、群体提及、消息持久化、自动匹配、手动指定与员工交接继续回归。
