# 慕雅居设计规范 · Commerce OS

依据：ui-ux-pro-max 的 SKILL.md 与 references/quick-reference.md。云端脚本资源读取失败，未生成或宣称数据库检索结果。以下为基于可读规则制定的项目设计系统。

## 产品与布局

电商团队日常使用的数字员工工作台。现有技术栈为原生 HTML、CSS、JavaScript 与 Node，不引入无关框架。

首页：纯文字产品名称“AI数字员工协作工作台”，无 logo 或星环；深色侧栏；左侧目标输入与快捷场景；右侧协作团队；下方真实任务记录。首屏主操作为生成执行计划。任务详情按目标、阶段、时间线、交付物、人工确认排列。

## 色彩

用户指定：黑白灰 + 一个主色调。背景 #F7F7F8、表面 #FFFFFF、正文 #202124、辅助文字 #62646A。
唯一主色 #315DDD，hover #254BB9，仅用于主要操作、当前导航、选中与焦点。角色图标和状态背景均使用中性灰，状态由文字区分。
侧栏 #202020，侧栏文字 #D5D5D5。移除红色、绿色及其他装饰配色。

## 输入聚焦

目标输入区为单一组合控件。textarea 不绘制自身 outline 或 shadow，由外层 .goal-composer:focus-within 显示 #8197D9 细描边及极轻外阴影。鼠标点击和键盘进入使用同一聚焦反馈，避免双重方框。其他按钮继续保留可见键盘焦点。

## 字体与间距

系统无衬线字体，中文优先 PingFang SC / Microsoft YaHei。正文 14–16px，注释 12px，章节 18px，首页标题 42px；手机标题 30px。正文行高 1.65。数字等宽。
4/8px 间距体系，桌面主区边距 40px，手机 20px。卡片圆角 16px，控件 8–10px。阴影只用于目标输入容器和弹窗。

## 交互与可达性

主要按钮至少 44px 高；SVG 图标统一 1.6px 线宽。可见焦点、真实 label、就近错误提示、跳至正文链接。
手机保留带文字的底部导航，最多五项，避免侧栏挤占正文。底部预留安全区域。正文输入 16px 避免 iOS 自动缩放。
微动效只作用于 opacity/transform，150–200ms；支持 prefers-reduced-motion。不使用持续装饰动画。

## 验证

截图检查 1440px 与 375px；导航、目标规划、团队调整、执行审批、后续迭代回归。验证无横向溢出，键盘可聚焦主操作，新增文本/背景配色达到 4.5:1。

## V5 群聊工作台

保留“新建目标”主入口：目标描述与 Agent 选择在同一个对话框中完成。提交后进入对应协作群；群聊是协同工作台的交互形式。工作台展示已有群聊，三栏为群列表、聊天消息与输入区、成员和交付物。窄屏收起右栏，仍通过“发送给”选择群成员，并从消息内下载交付物。

人类、数字员工、Agent 使用文字身份标记；每条 AI 回复引用对应人类消息。消息更新时保留草稿、输入焦点、光标及阅读位置；接近底部时才跟随新消息。暂停 AI 不阻止人类发言。消息输入与创建弹窗只显示一层聚焦提示。

## V6 目标协作工作区（2026-11-05）

当前产品采用纯文字“AI数字员工协作工作台”，黑白灰结构与#315DDD蓝色强调。以两步目标创建、目标列表、五个目标标签、上下文侧栏构建工作区。手机保留五个一级导航，并将右侧信息变为可打开的目标详情。状态卡必须区分草案、批准、提交、核验、观察和验收。不要用装饰图形、假经营指标或多色Agent头像替代业务信息。

使用ui-ux-pro-max可读设计规则进行审查；本环境未成功读取其搜索脚本与设计数据库，不声称运行了数据库检索。输入框为单一焦点边框，键盘按钮保持可见焦点；主要业务操作至少44px。真实产品能力边界在PRD中定义。

## V0.3 员工与能力中心（2026-11-06）

沿用现有色彩与字体。一级导航五项：协同工作台、任务中心、数字员工、能力中心、运行记录。员工列表显示装配能力和缺项，不将岗位模板当成完整能力。能力目录的134项规划与10个可执行Skill分开统计。模型连接区分独立API与个人ChatGPT套餐本机Codex。手机使用单列卡片，表单可滚动，输入标签和键盘焦点保持可见。
